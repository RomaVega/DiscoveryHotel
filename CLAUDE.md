# CLAUDE.md — Orlowsky Discovery Hotel Website

Static marketing site for Orlowsky Discovery Hotel, Candidasa, Bali. **Next.js 15 App Router** with `output: "export"`, deployed on **Netlify** (`orlowsky.id`). All content in JSON — no database, no CMS, no backend.

### i18n

English routes live at `/foo`, Russian routes at `/ru/foo` — each page is duplicated. Both wrap the tree in `LanguageProvider` (defaultLocale `"en"` or `"ru"`). Content JSON uses `LocalizedString` (`string | { en, ru }`); resolve with `useLanguage().t(...)` for content and `.tl` for UI strings. When editing a page, change **both** the EN and RU copies or accept the drift.

**Which locale a visitor lands on** is decided before first paint by the blocking script in [lib/lang-redirect.ts](lib/lang-redirect.ts), mounted first in `<head>`. Precedence: `?lang=en|ru` (remembered), then the stored `odh-lang` preference, then — only for a visitor with neither — their **primary** browser language. This is a redirect rather than a prompt because it exists to beat the browser's own "translate this page" offer, which appears at first paint: Edge's and Chrome's translators replace our text nodes with their own elements and React then throws on the next `removeChild`. [LanguageSuggestion](components/layout/LanguageSuggestion.tsx) still handles the *secondary*-Russian case as a soft card, where there is no translate offer to outrun.

**The hotel's name carries `translate="no"`** at all five render sites — the [Navbar](components/layout/Navbar.tsx) wordmark and logo link, the [Footer](components/layout/Footer.tsx) brand block, the [hero](components/sections/HeroImage.tsx) `<h1>`, and the [ErrorFallback](components/layout/ErrorFallback.tsx) eyebrow. A proper noun should never be machine-translated, and without the attribute Edge renders "Orlowsky Discovery" as "Открытие Орловского". Put it on the nearest wrapping element rather than each span, so one attribute also covers the logo's `alt`, which translators rewrite too.

**Do not blanket-apply `translate="no"` to animated regions.** It was considered as crash insurance for the six `AnimatePresence` blocks and rejected: the site has proper EN and RU versions, but visitors in any other language legitimately use browser translation, and marking the nav or FAQ untranslatable breaks the page for them to guard a shape this codebase does not have — bare text nodes sharing a parent with a mounting/unmounting element, which is what actually makes React's reconciler throw. Text here is consistently wrapped in elements. The defence against the translator crash is keeping Russian speakers off EN routes in the first place (see above), not opting out of translation everywhere.

**`<html lang>` is not set by the layout.** `output: "export"` gives all 38 routes the root layout's `lang="en"`, so `scripts/fix-ru-lang.js` rewrites the opening `<html>` tag of the 19 exported Russian pages as a `postbuild` step, and `LanguageProvider` keeps the attribute in step across client-side switches. Both halves are needed: a `router.push()` between locales never reloads the document, and the build-time fix cannot help there. The script fails the build rather than skipping a page it does not recognise — a Next release that changes the exported markup must not quietly ship `lang="en"` on every Russian page. Don't reintroduce an inline `<script>` for this: React inserts one via innerHTML on a client navigation, and scripts inserted that way never execute, which is why the previous attempt only ever worked on a hard load.

Matching only the primary language is deliberate — an `en-US`-first visitor who also lists Russian must stay on EN, since /ru would invite the reverse translate offer. The script is emitted as a string and [its tests](__tests__/lib/lang-redirect.test.ts) execute that exact string, so **add a case there rather than editing the script by eye** — a mistake in it can trap every visitor in a locale or a redirect loop.

## Architecture Rules

- **Pages are thin.** Import JSON → pass props to sections → return sections in order. No state, no effects, no styling in page files.
- **Data flow:** `content/*.json` → `lib/content.ts` (typed loaders) → page → section → static HTML → CDN.
- **No `any`.** Strict mode. All types in `lib/types.ts`. Add type before adding JSON field.
- **No runtime API calls** (except the GuestPro iframe).
- **Server Components by default.** Only add `"use client"` when component uses hooks/browser APIs. Comment the reason: `"use client"; // Uses IntersectionObserver`.
- **No additional UI libraries.** Only: `framer-motion`, `class-variance-authority`, `clsx`, `tailwind-merge`, `lucide-react`, `tw-animate-css`. `@base-ui/react` is a transitive shadcn dep — never import from it directly.
- Aceternity budget is final — no fourth component. Each Aceternity component adds ~15–30 KB and requires copy-paste maintenance with no upstream updates. Build new effects with Framer Motion + CSS.

## Canonical Page Pattern

Inner pages use `InnerPageLayout` (it composes `Navbar`, `Footer`, `WhatsAppButton`). The home pages (`/` and `/ru`) compose those manually because the hero is full-bleed video — see [app/page.tsx](app/page.tsx).

```tsx
// app/rooms/page.tsx — canonical inner-page shape
import { getRoomsPageData, getContactData } from "@/lib/content";
import { InnerPageLayout } from "@/components/layout/InnerPageLayout";
import { PageHero } from "@/components/sections/PageHero";
import { RoomsDetail } from "@/components/sections/RoomsDetail";
import { SITE_URL } from "@/lib/site";

export const metadata = {
  // Complete and self-contained — the root layout sets NO title template, so
  // nothing appends the brand for you. Include it here, once. `check-titles.js`
  // fails the build on a title naming the hotel twice.
  title: "Rooms & Villas in Candidasa, Bali — Orlowsky Discovery Hotel",
  description: "…",
  alternates: { canonical: `${SITE_URL}/rooms` },
  openGraph: { /* … */ },
};

export default function RoomsPage() {
  const data = getRoomsPageData();
  const contact = getContactData();

  return (
    <InnerPageLayout contact={contact}>
      <PageHero
        image="/images/rooms/pool-villa.webp"
        imageAlt="Aerial view of pool villas surrounded by tropical gardens"
        heading={data.heading}
        subtext={data.subtext}
        noOverlay
      />
      <RoomsDetail data={data} />
    </InnerPageLayout>
  );
}
```

Mirror the page under `app/ru/rooms/page.tsx` with translated metadata and `alternates.languages` set for both locales.

## Design Tokens (defined in `app/globals.css` under `@theme` — never raw hex in components)

- `accent-text` — **the teal that may carry text on light grounds.** Resolves to `deep-teal`. Reach for the role, not the hue: the contrast decision is made once in `@theme` rather than at every call site. Enforced by `npm run check:contrast`.
- `brand-teal` (#0abab5) — accent strokes, focus rings, icons, fills. **Never as text on a light ground:** 2.13:1 on sand, 2.27:1 on ivory, 1.88:1 on parchment — it fails AA at every size the site uses, including the 3:1 large-text floor. It *is* correct as text on the dark footer (6.66:1 on espresso), where the polarity flips and `deep-teal` would instead fail at 2.64:1. Mark such cases with a `contrast-ok:` comment carrying the measurement.
- `cta-teal` (#4ca8b5) — softer teal used inside `PrimaryButton` solid fill where the brighter `brand-teal` would clash. **A button fill, never a section background.** White on it is 2.77:1 — below even the 3:1 large-text floor — and it spent time as the ground of all ten CTA bands with white headings on it. `npm run check:contrast` RULE C now fails the build if `text-white` appears in a file that paints `bg-cta-teal`.
- `deep-teal` (#2a6b74) — hover state, footer, dark sections, scrolled nav, **and the ground for every full-bleed CTA band** (white heading 6.08:1, `text-white/80` body 4.54:1 — `/70` is 3.91:1 and fails at body sizes). Band headings are `font-medium`: Cormorant's hairlines at 300 go fragile on a dark ground.
- `logo-gold` (#c9a84c) — hero star rating and other gilded accents.
- `sand` (#f5f0e8) — page bg | `ivory` (#faf8f4) — card/modal bg | `parchment` (#e8e3d5) — scrolled-nav bg, loading screen.
- `charcoal` (#1a1a1a) — body text, headings | `stone` (#8a8070) — captions, secondary.
- `espresso` (#2a1f17) — footer dark surface.
- `white` (#ffffff) — text on dark bg.

## Typography & Spacing

- **Headings:** Cormorant Garamond (300 display, 400 smaller). Never below 20px.
- **Body/UI:** Inter (400 body, 500 nav/labels, 600 buttons). 16px base, `leading-relaxed`.
- **Spacing:** 8px grid. Sections: `py-24`/`py-32`. Heading mb: `mb-16`. Content: `max-w-7xl` centered. Generous whitespace is the core design principle — never reduce spacing to fit content.

## Animation Rules

- **Scroll fade-in:** opacity 0→1, y 20→0, 0.6s easeOut via `<FadeIn>` wrapper.
- **Stagger:** 0.1s between cards, max 6 steps (0.5s cap).
- **Page transition:** opacity 0.4s, no slides. **Card hover:** scale 1.02, 0.3s. Never ≥1.1.
- **Only animate `opacity` and `transform`.** Never `width`, `height`, `top`, `left`, `margin`.
- **Name transition properties explicitly** — `transition-[background-color,scale]`, not `transition-all` (which animates layout properties too). **In a hand-written list the property is `scale`, not `transform`:** Tailwind 4 compiles `scale-*`, `translate-*` and `rotate-*` to the standalone `scale:`/`translate:`/`rotate:` CSS properties, so a list naming only `transform` animates nothing and the change snaps silently — which is exactly how `PrimaryButton` shipped a hover animation that never ran. Each of the three needs naming individually. The `transition-transform` utility is safe on its own (it expands to `transform, translate, scale, rotate`); it just cannot be combined with colours in one list, since the last `transition-property` wins.
- **Gate hover/press scales behind `motion-safe:`** so `prefers-reduced-motion` drops the movement while colour changes still ease. There is no global reduced-motion CSS reset — `MotionConfig reducedMotion="user"` in `MotionProvider` covers Framer Motion only, not CSS transitions.
- Respect `prefers-reduced-motion: reduce` — show static fallback.
- Framer Motion is decorative only. CSS transitions for functional state changes.

## Image Rules

- Always `next/image`, never `<img>`. Full-bleed: `fill` + `sizes="100vw"`. Grid: explicit `width`/`height`.
- Paths in JSON: `/images/...` (not `public/images/...`). Naming: `[section]-[descriptor]-[sequence].ext` — **kebab-case, no spaces** (legacy `Deluxe Cottage/` etc. folders are scheduled to be renamed).
- Every image needs descriptive `alt` from JSON. Decorative: `alt=""` + `aria-hidden="true"`.
- Because `output: "export"` disables Next's built-in optimizer, [lib/image-loader.ts](lib/image-loader.ts) proxies image requests to Netlify Image CDN (`/.netlify/images`) in production. The CDN resizes on demand at the edge and negotiates AVIF/WebP via the Accept header. In dev the loader passes paths through unchanged.
- **Cache-busting is automatic — don't rename a file to force a refresh.** `netlify.toml` serves `images/*` and `video/*` `immutable` for a year under filenames that are not content-hashed, so a file replaced in place would otherwise keep serving the old bytes. The prebuild hashes every referenced image *and* video into `ASSET_VERSIONS` in [lib/image-manifest.ts](lib/image-manifest.ts); the loader appends `?v=<hash>` for images, and `versionedAsset()` from [lib/site.ts](lib/site.ts) for anything that bypasses the loader — chiefly the hero `<video><source>` tags. Any **new** asset type served from `public/` under a long cache (a PDF, a downloadable rate card) needs one of these two paths, or it will go stale for a year. `ASSET_VERSION` in `lib/site.ts` is only the manual fallback for paths assembled at runtime that the build-time scanner cannot see.

## Key Patterns

- **SectionHeading:** optional uppercase label (Inter, brand-teal, `text-sm tracking-widest`), H2 with text-reveal (Cormorant Garamond), optional subtext.
- **PrimaryButton:** `inline-block bg-brand-teal hover:bg-cta-teal motion-safe:hover:scale-[1.04] motion-safe:active:scale-[0.97] text-charcoal font-sans font-semibold px-8 py-3 rounded-full tracking-wide uppercase text-sm transition-[background-color,scale] duration-300 ease-out` + focus-visible ring. The transition names `scale`, not `transform` — see [Animation Rules](#animation-rules); it was `transition-colors`, so the two scale steps snapped and the hover animation never actually ran. See [components/common/PrimaryButton.tsx](components/common/PrimaryButton.tsx) — supports `href` and `external`. A call site that cannot render the component imports `PRIMARY_BUTTON_BASE` from it rather than hand-copying the classes, the way `SECONDARY_BUTTON_BASE` is used: `BugReport`'s `mailto:` cannot go through `LocalizedLink`, and `external` would force `target="_blank"` and strand an empty tab. **The label is charcoal, not white** (white on `brand-teal` is 2.41:1; charcoal is 7.21:1), and hover is `cta-teal` rather than `deep-teal`, which would drop dark text to 2.86:1. The fill is unchanged — the brand teal stays.
- **SecondaryButton:** `inline-block bg-transparent border border-deep-teal text-accent-text hover:bg-brand-teal hover:text-charcoal motion-safe:hover:scale-[1.04] motion-safe:active:scale-[0.97] px-5 py-2 rounded-full tracking-wide text-xs font-sans font-semibold whitespace-nowrap transition-[color,background-color,border-color,scale] duration-300 ease-out`. The explicit property list replaced a `transition-all`, which also animated layout properties. Use for secondary CTAs (e.g., "View All", "Learn More"). Border and text are `deep-teal`/`accent-text`, not `brand-teal`: as text that was 2.13:1 on sand, and the border missed the 3:1 non-text floor too. Do not inline these styles — use the `SecondaryButton` component in `components/common/`. Supports `href` (internal or `external`) and `onClick` (renders as `<button>`). Two call sites cannot use the component (a `<span>` inside a card-wide `<a>`; anchor-in-anchor is invalid HTML) — they import `SECONDARY_BUTTON_BASE` / `SECONDARY_BUTTON_HOVER` from it instead of hand-copying the classes.
- **WhatsApp:** `https://wa.me/[number]?text=[encoded]`. Number from `process.env.NEXT_PUBLIC_WHATSAPP_NUMBER`, international format, no `+`, no spaces. Never hardcode the number in components.
- **GuestPro:** iframe from `https://secure.guestpro.net/odch`. On failure/timeout >5s, fall back to "Book Now" button opening URL in new tab.
- **Gallery:** all images come from `galleryPreview.images` in [content/home.json](content/home.json) — one array feeding both surfaces, so a photo added or removed there changes both at once. [GalleryMosaic](components/sections/GalleryMosaic.tsx) (`/gallery`) renders the full set in a CSS-columns masonry with category filter pills; [GalleryPreview](components/sections/GalleryPreview.tsx) (home) shows one slide plus a **fixed 5-column** thumbnail grid. **The home strip renders only a whole number of rows** — it trims the array to a multiple of `THUMB_COLUMNS` — so it can show fewer photos than `/gallery`, and its slide cycles only the trimmed set; a 26th photo is invisible on the home page and present on `/gallery`. Add photos in fives if you want every one of them fronted on the home page. The grid is a fixed 5 rather than `auto-fill`, because auto-fill re-flowed the row width with the viewport (3 tracks at 320px, 5 at 414px, 9 at 768px) and so left an orphan tile at some width for any photo count. Both surfaces are fully SSG — that trim is a deterministic slice at render, not lazy loading; no sentinel, no network. Lightbox via shadcn Dialog with arrow-key nav.
- **BugReport:** footer bug reporter — a `Bug` icon at the bottom-left of the bottom bar opens a shadcn Dialog carrying a note from the maintainer and one pre-composed `mailto:` to the maintainer — **not** reception's `contact.email`. That address is a constant in the component and deliberately **not** in `content/contact.json`: `contact` is a prop to the client `Footer`, so React serialises the whole object into every page's RSC payload, putting a plain-text address in all 39 pages at once. There is no backend to POST a form to under `output: "export"`, so the speed has to come from leaving the visitor nothing to type: page URL, viewport and user agent are filled into the body when the dialog opens — not at render, since prerendered markup has no location to read.

- **Error boundaries:** [app/error.tsx](app/error.tsx) catches anything below the root layout; [app/global-error.tsx](app/global-error.tsx) catches the layout itself and replaces the whole document. Both render [ErrorFallback](components/layout/ErrorFallback.tsx) — inline CSS and raw hex on purpose, since a failed CSS chunk is one of the things it exists to survive, so **the "never raw hex in components" rule does not apply to that file**. Both also call `reportBoundaryError` from [lib/report-error.ts](lib/report-error.ts), which sends a GA4 `exception` event carrying `translator`, `browser_lang`, `page_locale`, `error_digest` and `fatal`. `translator` is the one to watch: Edge's and Chrome's page translators swap our text nodes for their own elements, and React then throws on the next `removeChild`/`insertBefore` — a real crash source for Russian-speaking visitors on EN routes. The reporter never creates `dataLayer`, so dev and deploy previews send nothing, and it caps at three hits so a crash loop can't flood the property. **Custom parameters stay invisible in GA4 reports until registered under Admin → Custom definitions** — collection starts immediately, reporting does not.

## Accessibility (WCAG 2.1 AA — non-negotiable)

- 4.5:1 body text, 3:1 large text. Focus: `focus-visible:ring-2 focus-visible:ring-brand-teal focus-visible:ring-offset-2`.
- Semantic HTML, one `<h1>` per page. Focus trap in modals, return focus on close.
- Skip link as first focusable element. Hero video: `muted autoPlay playsInline` + pause button.

## Content Editing

- All changes are JSON edits in `content/`. **Add type in `lib/types.ts` before adding JSON fields.**
- Offers: set `"active": false` — never delete expired offers.
- **Ratings in `content/reviews.json` are verified claims, not decoration.** Each aggregate carries a
  `verifiedOn` date, and `RatingSummary` publishes the *oldest* one across the four platforms as
  "Scores verified: <month> <year>" — so the stamp can never read fresher than the least-recently-checked
  figure. Only move a `verifiedOn` after actually opening that platform and reading the score and count
  off the page; bumping the date alone turns the word "verified" into a false claim. Counts drift **down**
  as well as up (platforms prune reviews — Booking went 140 → 135 between July and August 2026), so
  re-read both numbers rather than assuming they only grow. Tripadvisor 403s every automated request and
  needs a human. A `SessionStart` hook (`.claude/settings.json` → `scripts/check-rating-freshness.js`)
  flags the stamp when its month is no longer the current one; it never edits the file.
- New page: create page file (follow canonical pattern) → add to navbar → create sections → add JSON + types → verify with `tsc && build`.

## Environment Variables

- `NEXT_PUBLIC_WHATSAPP_NUMBER` (required) — used in all WhatsApp links, read via `process.env.NEXT_PUBLIC_WHATSAPP_NUMBER`. This is the single source of truth for the number; do not hardcode it elsewhere.
- `NEXT_PUBLIC_GA_MEASUREMENT_ID` (optional) — GA4 property. [components/layout/GoogleAnalytics.tsx](components/layout/GoogleAnalytics.tsx) renders nothing when unset, so dev/previews stay out of the data. Scope it to Netlify's production context. Adding another Google/analytics origin means widening `script-src`/`connect-src` in [netlify.toml](netlify.toml). The same tag carries the boundary crash reports from [lib/report-error.ts](lib/report-error.ts); `connect-src` already allows `*.google-analytics.com`, so that needed no CSP change. With the var unset there is no tag, and crashes go unreported — which is the state the site shipped in until September 2026, when a guest had to report a blank page by hand.
- **Google Tag Manager has no env var.** Container `GTM-KHDV2SW2` is hardcoded in
  [components/layout/GoogleTagManager.tsx](components/layout/GoogleTagManager.tsx) — a container ID
  ships in every page, so it is not a secret. What the component gates on is Netlify's build-time
  `CONTEXT`: deploy previews and branch deploys render nothing, so only `orlowsky.id` feeds the
  container. The two halves (`GoogleTagManagerHead` in `<head>`, `GoogleTagManagerNoScript` first in
  `<body>`) are mounted in [app/layout.tsx](app/layout.tsx), which `/ru` nests inside — one mount
  covers both locales. **A tag added inside the GTM UI that calls a new origin is blocked by the CSP
  in [netlify.toml](netlify.toml) until that origin is added there**; GTM cannot widen a response
  header, and the failure looks like a tag that silently never fires. GTM **Preview /
  Tag Assistant** needs its own origins in that CSP (`tagmanager.google.com` in
  `script-src` + `style-src`, `www.google.com` in `connect-src`, `data:` in `font-src`)
  — without them Tag Assistant reports "0 Google tags found" and times out even though
  the container is installed correctly. Note that ad-blocking browsers (Brave's Shields,
  uBlock) block `googletagmanager.com` outright, so verify in a clean Chrome profile
  before concluding the site is at fault.
- `GOOGLE_SITE_VERIFICATION` (optional) — Search Console HTML-tag token, emitted via `metadata.verification.google`. Not `NEXT_PUBLIC_`; it is build-time only. Safe to drop once DNS TXT verification is in place.
- Never put secrets in `NEXT_PUBLIC_` — they're inlined into client JS.

## Common Mistakes

- Don't put logic (`useState`/`useEffect`/conditionals) in page files — move to section components.
- Don't add `"use client"` to fix type errors — fix the types instead.
- Don't nest `<section>` elements — sections are siblings within `<main>`.
- Don't skip `alt` attributes or use non-descriptive text.
